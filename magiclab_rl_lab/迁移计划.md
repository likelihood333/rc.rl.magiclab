# HoST 跌倒爬起任务迁移到 magiclab_rl_lab 的适配方案

## 1. 目标与约束

- 目标：把 `HoST` 中跌倒爬起（ground / prone / platform / slope / wall）相关的训练、环境配置、评估流程迁移到 `magiclab_rl_lab`。
- 约束：尽量不改动 `magiclab_rl_lab` 现有代码，优先通过新增文件实现。
- 保持现有入口习惯：继续用 `scripts/rsl_rl/train.py`、`scripts/rsl_rl/play.py`，只新增 task id 和对应配置。

---

## 2. 两个仓库的核心差异（迁移关键）

### HoST（旧）

- 架构：`Isaac Gym + legged_gym + rsl_rl`，环境主体在 `legged_gym/envs/base/host_*.py`。
- 任务注册：`legged_gym/envs/__init__.py` 里 `task_registry.register(...)`。
- 配置风格：大类配置（`G1Cfg/G1CfgPPO`）+ 环境类直接写奖励、终止、观测。
- eval：独立脚本 `scripts/eval/eval_*.py`，内部有 `EvalLogger` 统计成功率、能耗、平滑度、足端移动距离等。

### magiclab_rl_lab（新）

- 架构：`Isaac Lab ManagerBasedRLEnv`。
- 任务组织：`source/magiclab_rl_lab/magiclab_rl_lab/tasks/...`，通过 `gym.register()` 注册任务。
- 配置风格：`velocity_env_cfg.py` 中拆分 `Scene / Actions / Observations / Rewards / Events / Terminations / Curriculum`。
- 训练/推理：通用脚本 `scripts/rsl_rl/train.py` / `play.py`，读取 task 注册的 cfg。

**结论**：HoST 不是“可直接拷贝环境类”，需要按 Isaac Lab MDP 术语拆分迁移。

---

## 3. 迁移总体策略（最小侵入）

采用“并行新增一套 standingup 任务包”的方式，不破坏已有 locomotion velocity 任务：

- 不改现有 `locomotion/robots/z1/12dof/velocity_env_cfg.py`。
- 新建 `tasks/standingup/...`，把 HoST 逻辑逐步搬进去。
- 通过新增 `gym.register()` 提供新 task id。
- eval 单独新增脚本，不侵入现有 `play.py` 和 `train.py`。

## 5. HoST 到 Isaac Lab 的功能映射

### 5.1 任务注册映射

HoST task：

- `g1_ground`
- `g1_ground_prone`
- `g1_platform`
- `g1_slope`
- `g1_wall`

建议在 magiclab 注册为：

- `Magiclab-Z1-12dof-Standup-Ground`
- `Magiclab-Z1-12dof-Standup-Prone`
- `Magiclab-Z1-12dof-Standup-Platform`
- `Magiclab-Z1-12dof-Standup-Slope`
- `Magiclab-Z1-12dof-Standup-Wall`

### 5.2 训练流程迁移

- 复用现有 `scripts/rsl_rl/train.py`。
- 新任务只需提供：
  - `env_cfg_entry_point`
  - `play_env_cfg_entry_point`
  - `rsl_rl_cfg_entry_point`
- PPO 参数先按 HoST 近似设置（如 actor/critic hidden dims、entropy、max_iterations）。

### 5.3 环境与随机化迁移

HoST 关键项需要在新 `EventCfg + CurriculumCfg + RewardsCfg` 里实现：

- 初始姿态（仰卧/俯卧/侧卧）重置策略。
- 随机化：摩擦、恢复系数、link 质量、payload、COM、kp/kd、delay。
- “pulling force” 课程（HoST 早期阶段上拉力）：
  - 在 Isaac Lab 中建议做成 interval/reset event + curriculum 逐步衰减。
- 动作缩放课程（HoST `action_rescale` 随成功爬起逐步减小）：
  - 建议做成 curriculum term 作用于 action scaling 参数。

### 5.4 奖励迁移

HoST 的 reward group 逻辑建议映射到 Isaac Lab 多个 `RewTerm`：

- task：姿态、头部高度（站起判据）
- regu：`dof_acc`、`action_rate`、`joint_power`、`joint_tracking_error`、`limit penalty`
- style：髋/膝/腰/肩约束、脚间距、胫骨方向、地面平行性
- target（站起后）：姿态稳定、基座高度、上身目标姿态、低速度

建议先迁移“必要子集”再逐步加全量项，避免初版 reward 过多导致难调参。

### 5.5 Eval 迁移

HoST eval 指标来源于 `EvalLogger`：

- success rate
- feet movement
- smoothness
- motion tracking error
- energy
- smoothness before standup

在 `scripts/rsl_rl/eval_standup.py` 中实现相同统计口径：

- 支持 `--task --checkpoint --num_episodes`。
- 输出终端统计 + `csv/json`。
- 可选保存每个 episode 的明细（便于回归对比 HoST）。

## 6. 分阶段实施建议（推荐）

### 阶段 A：最小可跑通（1 个任务）

- 先只做 `Ground`（仰卧起身）：
  - 新建 standup_ground_env_cfg + 基础 rewards + 基础 events + 新 task 注册。
- 目标：`train.py --task Magiclab-Z1-12dof-Standup-Ground` 可训练并收敛到可起身。

### 阶段 B：扩展姿态与地形

- 加 `Prone / Platform / Slope / Wall` 四个 cfg。
- 主要差异放在：
  - 初始姿态 reset
  - 地形生成器配置
  - 少量 reward / termination 阈值

### 阶段 C：对齐 HoST 指标

- 新增 `eval_standup.py`，输出与 HoST 近似的评估指标。
- 与 HoST checkpoint（或曲线）做对照，修正奖励权重与课程节奏。

## 8. 风险点与提前规避

- **HoST 的 reward 是“乘积+分组”风格**，Isaac Lab 常见是加权求和；需要分阶段映射，避免学习不稳定。
- **pull force 与 action scale curriculum** 若直接照搬，可能和新框架事件周期冲突；建议先固定再逐步打开课程。
- **评估口径不一致** 会导致“看起来退化”；需先统一成功定义（头高/基座高度/是否二次摔倒）。
- **机器人资产差异（12dof vs 23dof）**：先锁定 Z1-12dof，后续再扩自由度版本。

## 11. 风险点的迁移检查清单（可执行版）

### 11.1 Reward 乘法到加法的映射检查

- 检查项：
  - 先只保留 task 主奖励（如 upright/head-height）与最小正则项（action rate / energy）。
  - 关闭 style/target 的复杂项，确认可稳定起身后再逐项打开。
- 验收标准：
  - 前 1k~2k iter 内成功率有明确上升趋势（不是长期 0）。
  - 没有出现“奖励很高但动作明显发散”的现象。
  - 每新增一类奖励项，成功率下降不超过可接受阈值（建议 < 10%）。

### 11.2 pull force 与 action scale 课程节奏检查

- 检查项：
  - 先固定 `pull_force` 和 `action_scale`（常量），作为基线。
  - 再单独打开 `pull_force curriculum`，观察其随 episode 的衰减是否符合预期。
  - 最后打开 `action_scale curriculum`，避免两者同时引入不确定性。
- 验收标准：
  - 课程参数变化曲线单调且平滑，无抖动或突然跳变。
  - 课程开启后训练仍可收敛，不出现“刚学会又退化”的长周期震荡。
  - 相比固定参数基线，最终成功率或稳定性有提升。

### 11.3 Eval 口径一致性检查

- 检查项：
  - 明确统一成功定义：建议 `头高阈值 + 站起后不二次摔倒`。
  - 统一统计窗口：每个 episode 长度、是否忽略 unactuated 前若干步。
  - 统一指标名称和计算方式（success / smoothness / energy / feet movement）。
- 验收标准：
  - 同一 checkpoint 在旧/新脚本上的结果差异处于可解释范围。
  - 指标字典字段固定，重复运行结果波动可控。
  - 能输出按 episode 的原始明细（便于问题追踪）。

### 11.4 12DoF 与 23DoF 资产差异检查

- 检查项：
  - 明确当前迁移基线仅针对 Z1-12DoF。
  - 所有 joint/body 名称映射均来自 12DoF URDF，不复用 23DoF 特有名称。
  - 观测维度、动作维度、奖励中的关节索引全部自动校验。
- 验收标准：
  - 环境初始化不报 missing joint/body name。
  - step 时不出现维度不匹配错误。
  - 训练日志中的 action/observation shape 与配置一致。

  - head_joint type="fixed"，yaw 轴
